# Деплой DEXLO

Этот проект готов к развёртыванию как витрина, каталог, корзина, поддержка, документы и административная панель. Подключение реального эквайринга и автоматической выдачи товара выполняется отдельным этапом после одобрения провайдера.

## До первого запуска на сервере

1. Установите Docker Engine и Docker Compose Plugin.
2. Скопируйте проект и создайте `.env` из `.env.example`.
3. Задайте новые уникальные секреты: `BOT_TOKEN`, `RESELLCODES_API_KEY`, `POSTGRES_PASSWORD`, `ADMIN_PASSWORD_HASH` и `ADMIN_JWT_SECRET`.
4. Задайте `STORE_NAME=DEXLO`, контакты поддержки и актуальные дату/контакт в юридических документах.
5. Не публикуйте PostgreSQL наружу. Админ-панель по умолчанию слушает только `127.0.0.1:8080`.

## Запуск

```bash
docker compose up -d --build
docker compose ps
docker compose logs --tail=100 bot
```

Бот использует long polling: публичный Telegram webhook не нужен. Для IP `2.27.42.108` добавлен `Caddyfile` с публичным сертификатом Let's Encrypt. IP-сертификат действует около шести дней; Caddy автоматически продлевает его и сохраняет данные в volume `caddy_data`.

Перед запуском Caddy убедитесь, что IP действительно закреплён за сервером, а входящие TCP-порты `80` и `443` открыты в firewall и панели провайдера. Запуск на сервере:

```bash
docker compose --profile public up -d --build
docker compose logs -f caddy
```

Откройте `https://2.27.42.108`. Caddy проксирует его на админ-панель DEXLO, а вход в панель по-прежнему требует учётные данные администратора. Для постоянного production-доступа безопаснее впоследствии привязать домен и ограничить админ-панель через VPN или IP allowlist.

## Резервные копии

Контейнер `db-backup` создаёт PostgreSQL-дампы во внутреннем Docker volume. Это защита от логических ошибок внутри сервера, но не резервная копия сервера целиком.

До запуска в production настройте ежедневное копирование этих дампов в отдельное защищённое хранилище и выполните хотя бы одно тестовое восстановление. Срок хранения задаётся через `BACKUP_KEEP_DAYS`.

## Проверка перед отправкой платёжному провайдеру

- Бот доступен, `/start`, каталог, карточка товара, корзина, «Документы» и «Поддержка» открываются.
- В документах доступны политика конфиденциальности, пользовательское соглашение, цены и правила оплаты/возвратов.
- Цена, валюта, регион и способ активации отображаются до оформления.
- В оформлении указано, что оплата находится на стадии подключения; деньги не принимаются до выдачи ключей провайдера.
- Админка доступна только администратору; проверены вход, просмотр пользователей, заказов, промокодов и ответы поддержки.
- API-ключ поставщика остаётся только на сервере и не передаётся в клиентский интерфейс.

## После одобрения провайдера

Нужны его API-ключи, URL и формат подписанных webhook-уведомлений, список методов оплаты, правила чеков и возвратов. После этого следует реализовать и проверить: создание платежа, проверку подписи и идемпотентность webhook, изменение статуса заказа, запрос заказа к поставщику и выдачу цифрового товара только после подтверждённой оплаты.
